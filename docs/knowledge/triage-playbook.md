# SCVMM plugin — triage playbook

Symptom-first index of every bug investigated in the Copilot sessions (Sep–Oct 2026), cross-checked against `main` on 2026-10-19. Status legend:

* **Fixed (#n)** — merged to `main` in that PR.
* **Open PR #n** — fix exists on a branch / PR, not merged.
* **Unfixed** — root-caused, no fix landed (branch/commit may exist locally).
* **Not plugin** — environment, core, image, or QA-procedure issue.

Before anything else, run the first-five-minutes checklist in §0. Full architecture context: [architecture.md](architecture.md).

---

## 0. First five minutes

1. **Which plugin build is live?** `ls -l /var/opt/morpheus/morpheus-ui/plugins/` — jar name embeds `<timestamp>-<run>-<sha>`; map the sha with `git log --all --oneline | grep <sha>` and check whether it is on `main`. QA builds frequently predate the fix you are about to re-discover.
2. **Which appliance line?** 9.1.0.x vs 9.1.2.x differ in core fixes (`rc-9.1.0` lacks several embedded/console fixes).
3. **Clocks.** `date -u; timedatectl` on the appliance vs a guest vs your laptop. A skewed appliance breaks health checks and makes every timeline misleading.
4. **Pull the appliance log around the event** (`/var/log/morpheus/morpheus-ui/current`, `grep -a`), and the VMM Jobs view for the same window (VMM server local time may not be UTC). Filter on `ERROR|WARN|SCVMMPlugin|<serverId>|morpheus_server_<id>` — do not grep `"ip"` (matches `resizeApply`).
5. **Decide plugin vs environment** with these rules: SCVMM assigns an IP but the VM cannot talk → physical/network; SCVMM refuses at placement → SCVMM config or plugin script; VM never gets an IP in VMM → guest KVP / DHCP / vSwitch; failure identical with embedded SCVMM → inherited, still worth fixing but not a regression.
6. **Locate the stack line**, not the enclosing message ("Error in determining host and datastore" wrapped an NPE that never reached placement).
